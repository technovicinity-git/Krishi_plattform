# Krishi — Migration Scripts

We run migrations directly against Postgres instead of using the Supabase CLI,
because the CLI is currently blocked by the scoped-token permission bug.

## One-time setup

1. Make sure `web/.env.local` exists (copy from `.env.local.example` if needed).
2. Set `DATABASE_URL` — get the connection string from:
   **Supabase Dashboard → Connect → Session pooler → Connection string**
3. Replace `[YOUR-PASSWORD]` with the database password.
4. If the password contains `&`, `#`, `?`, `/`, `+`, `=`, `@`, or spaces,
   URL-encode those characters (e.g. `&` → `%26`, `#` → `%23`).
   Passwords generated by Supabase's "Generate" button are already URL-safe.

## Commands

- `npm run db:migrate` — apply pending migrations
- `npm run db:status` — list applied vs. pending migrations and verify checksums, without applying anything

The scripts read `web/.env`, then `web/.env.local` (either may be missing).
Checksums ignore line endings (CRLF vs LF), so Windows and Unix checkouts agree.

## How migrations work

- SQL files live in `web/supabase/migrations/`
- Naming convention: `YYYYMMDDHHMMSS_description.sql`
- Each migration runs in a transaction — if any statement fails, it rolls back
- Applied migrations are recorded in a `_migrations` table
- Once applied, a migration's content is **immutable** — the checksum guards against edits
- An advisory lock prevents two migration runs from colliding

## Creating a new migration

1. Create a new file: `web/supabase/migrations/20261008000001_add_users_table.sql`
2. Write plain PostgreSQL in it
3. Run `npm run db:migrate`

## If you ever suspect the DB password leaked

1. Go to **Supabase Dashboard → Settings → Database → Reset database password**
2. Update `DATABASE_URL` in `web/.env.local` with the new password
3. Done — the old password stops working immediately

## Switching back to the Supabase CLI later

When the CLI's scoped-token issue is fixed, we can switch back by running:
- `npx supabase link --project-ref mqmqlxoazkkakzczhmco`
- `npx supabase db push`

The migrations directory is fully compatible with the CLI — no conversion needed.
